# ADR 0027: 구성 요소 대조 — elements-v1 응답, 초록 인용 검사, 개발 플래그

- 상태: Accepted (2026-10-26, 개발 플래그 안의 프로토타입)
- 관련: `docs/strategy.md` 4절 "요소 대조 규칙 v1"·측정 결과, 9절 23번 / ADR 0024 (graph-v1) / ADR 0001 (provider 패턴) / ADR 0023 후보 (로컬 임베더)

## Context
- 지도(graph-v1)는 아이디어 전체와 가까운 문서를 보여 주지만, "내 아이디어의 어느 부분이 이미 문헌에 있는가"는 답하지 못한다.
- 그래서 다음 기능으로 구성 요소 대조를 만든다: 아이디어 → 구성 요소 → 요소별 가까운 문헌 → 요소×문헌 판정과 근거.
- 위험 두 가지
  - AI 가 근거 문장을 지어낼 수 있다.
  - "없음"을 "선행문헌이 없다(특허 가능)"로 읽을 수 있다.
- 평가 (2026-10-26, 판정 쌍 80개, 실행 7회) [확인]
  - "있음" 정밀도는 높았다 (Haiku 5.5 6/6·8/8·6/6).
  - 사람 present 의 대부분을 "일부"로 판정했다 (재현율 6~11/36).
  - 인용 검사 통과율은 32/34~46/47 이었다.
- 정답지 기준(present 의 뜻)과 기본 모델은 사람 재검토 뒤에 정한다. 운영 공개·논문 전 필수 (strategy.md 9절 23번).

## Decision
1. **응답 형식 `elements-v1`** (graph-v1 과 따로, 버전을 붙임). 필드: `query`, `scope`(검색 범위·문서 수·요소별 상위 k), `model`(공급자·모델·프롬프트 판), `elements`, `matches`(요소×문헌 판정과 인용·위치), `not_found`, `dropped`(버린 판정과 이유), `documents`(제목·연도·URL·종류, 초록 전문은 넣지 않음), `usage`, `note`.
   문헌 id 는 graph-v1 노드 id(`source:source_id`)와 같아, 지도에서 같은 문서를 고를 수 있다.
2. **근거는 초록 원문 인용만, 서버가 검사한다** (`backend/elements/quote_check.py`).
   - NFKC·따옴표/대시 정규화 뒤, 초록의 연속 부분 문자열이어야 한다. 말줄임 금지, 20자 이상.
   - present·partial 은 인용이 필수이고, absent 는 인용이 없어야 한다.
   - 통과하지 못한 판정은 근거로 세지 않고 `dropped` 에 이유와 함께 남긴다.
   - 검색 결과에 없는 문헌, 같은 문헌의 두 번째 판정, 판정이 빠진 문헌도 `dropped` 에 남긴다.
3. **판정 3단계와 표기**: present "있음" / partial "일부" / absent 는 화면에 **"못 찾음"**으로만 쓴다. 요소 단위로는 "이 검색 범위 안에서 못 찾은 요소"라고 쓰고, 검색 범위(코퍼스 이름·문서 수·요소별 상위 k)를 함께 보인다. 법적 판단이 아니라는 고지는 응답 `note` 와 화면에 둔다.
4. **"있음"과 "일부"를 둘 다 인용과 함께 보이고 판단은 사용자에게** (사용자 결정 2026-10-26). 평가에서 AI 의 "일부"가 사람의 present 를 많이 포함했기 때문이다.
5. **두 단계 API** (`backend/routes/elements.py`)
   - `POST /api/elements/propose {text}` → AI 요소 제안
   - 사용자가 화면에서 고친다
   - `POST /api/elements/chart {text, elements[]}` → 요소마다 임베딩(text-embedding-3-small) → pgvector 상위 5편 → AI 판정 → 인용 검사
   - 요소는 1~8개, 각 500자 이하. 아이디어는 2,000자 이하.
6. **공급자 인터페이스 뒤에 AI 를 둔다** (`backend/elements/judge.py`, `providers.py`).
   - 잠정 기본: Claude Haiku 5.5 (Messages API 를 httpx 로 직접 호출, 새 의존성 없음).
   - OpenAI 공급자도 있다. 로컬 모델(ADR 0023 과 함께)은 같은 인터페이스로 나중에 붙여 같은 평가(E1~E4)로 비교한다.
   - 키는 서버 환경 변수로만 받는다 (`ANTHROPIC_API_KEY`, 임베딩은 `OPENAI_API_KEY`). `backend/` 는 레지스트리 등 다른 곳을 읽지 않는다.
7. **프롬프트 `elements-prompt-v2`** (`backend/elements/prompts.py`)
   - 쪼개기: "1~8개, 아이디어가 담은 만큼", 지어내지 않기를 우선한다. v1 의 "3~8개"가 짧은 아이디어에서 지어내기 금지와 부딪혔다.
   - 판정: v1 그대로. 문헌 id 는 doc1… 별칭으로 보내 외부 식별자가 판단에 끼지 않게 한다.
   - v2 측정은 "조정 뒤"로 따로 기록한다.
8. **개발 플래그 안에서만**
   - 백엔드: `ATLAS_ENABLE_ELEMENTS=1` 일 때만 라우터를 붙인다.
   - 화면: `NEXT_PUBLIC_DEV_ELEMENTS=1` 빌드에서만 보인다. 그 밖의 빌드에서는 `next.config.mjs` 가 컴포넌트를 빈 컴포넌트로 바꿔 빌드 결과에 코드 조각도 남지 않는다.
   - 개발 실행은 [비공개: 개발 환경]에서 한다.
9. **외부 AI 전송 고지**: 화면에서 "입력한 아이디어와 요소, 검색된 문헌 초록이 외부 AI(Anthropic)로 전송된다"는 확인란을 체크해야 요소 제안·대조 버튼이 켜진다.

## Consequences
- 지어낸 인용은 화면에 나오지 않는다. 다만 맞는 인용이 판정을 정당화하는지는 사용자가 읽고 판단해야 한다.
- "못 찾음"은 검색 범위(지금은 개발용 코퍼스 160편, 요소마다 상위 5편)에 묶인다. 범위 밖 문헌은 판단하지 않는다.
- 요청 1회 비용 [추정, 측정 실행 기준]: 요소 3개 대조는 Haiku 로 1센트 아래. 평가 실행(11회 호출)이 약 $0.0075 였다.
- **운영에 열기 전 조건** (strategy.md 9절 23번)
  - 요청 수 제한·로그 수정 (9절 13·14번)
  - 외부 전송 고지의 법률 문구 검토, 공급자별 데이터 보존 조건 확인 (ADR 0030 후보 "외부 AI 로 아이디어를 보내는 기준", strategy.md 9절 23번)
  - 초록 이용 조건 (9절 9번)
  - 정답지 재검토와 기본 모델 확정

## 갱신 (2026-10-27): 부분 실패
- `elements-v1` 에 `failed: [{"element", "reason": "judge_failed"}]` 를 더했다. 기존 필드는 그대로이고, 옛 화면은 이 필드를 무시해도 된다.
- 판정 호출이 실패한 요소는 `failed` 에만 넣는다.
  - `not_found` 에 넣지 않는다: 실패는 "못 찾음"이 아니다.
  - 그 요소의 검색 문헌도 `documents` 에 넣지 않는다.
- 모든 요소가 실패할 때만 `AllElementsFailed` → API 502. 원인은 서버 로그에만 남기고 응답에는 일반 메시지만 넣는다.
- 화면: 실패한 요소의 행(휴대폰은 카드)에 "판정 실패 · 다시 대조해 보세요 (못 찾음이 아니에요)", 맨 아래에 "판정에 실패한 요소: e2" 를 보인다.
- AI 호출마다 사용량 한 줄을 서버 로그에 남긴다 (`backend/ai_usage.py`, 실패한 호출은 `outcome=error`). 아이디어·요소·초록·인용은 넣지 않는다.
